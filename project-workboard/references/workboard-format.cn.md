# 导图工作面板格式

[English（执行参考原文）](workboard-format.md) | 简体中文

本文件是中文阅读译本，规则以英文原文为准。新建或重新设计导图、修改数据结构或交互时读取。已有旧看板继续按原格式维护，迁移须由用户单独授权。

## 来源与数据结构

唯一内置案例为 [workboard-map.html](../assets/example/workboard-map.html)。它是可离线直接打开的单文件，唯一活动任务数据位于 id 为 workboard-data、type 为 application/json 的 script 元素中。引擎和界面读取这一份数据；浏览器不扫描项目、不拉取第二份任务清单，也不通过浏览操作写回任务数据。

将虚构示例替换为用户授权的实际项目。保持 JSON 有效，将字符串中的小于号转义为 \u003c，避免文本提前结束 script 元素。使用明确字段，不从任务编号猜测关系：

| 字段 | 内容 |
| --- | --- |
| meta.title、meta.description | 项目名称与简介 |
| meta.version、meta.sample | 可选版本标记和虚构示例提示；真实项目应移除示例内容 |
| meta.projectRoot | 相对于看板文件的项目目录，以斜杠结尾；根目录看板用 ./，下一级目录中的看板用 ../ |
| meta.storageKey | 非空、稳定且仅属于该项目的浏览器存储标识；每个新项目使用新标识 |
| meta.currentTaskId | 可选的现有任务编号；省略时显示项目总览，不根据任务状态自行选出唯一主线 |
| stages | 阶段数组：{id, name, environment, state, summary, acceptance, pending, evidence?}；state 为明确记录的阶段签收状态 |
| tasks | 任务数组：{id, stage, parent?, title, status, priority?, description?, acceptance?, deps?, verification?, evidence?, updatedAt?} |
| sources | 可选材料数组：[{label, path}] |
| history、decisions | 可选记录数组：{date, title, detail, stage?, task?, evidence?}；项目总览展示全部记录，阶段／任务展示关联记录 |
| taskGroups | 可选的显式展示分类，见下文分类规则 |
| statuses | 可选状态映射对象：已有状态代码对应 {label, kind}；kind 为 todo、doing、waiting 或 done |

编号可以是非空字符串或有限数字。在阶段数组内、任务数组内，编号的字符串形式分别唯一；数字编号和相同文本编号视为同一引用。阶段、任务与分类使用不同命名空间。每项任务都属于现有阶段。parent 缺省、为 null 或空字符串表示阶段下的顶层任务；否则必须指向同一阶段内的现有任务。deps 是任务编号数组，与 parent 分开。缺少的材料和未完成事实仍须保留。

默认状态代码为 todo、doing、waiting、done，语义以技能原文为准；waiting 必须同时满足当前安排推进和必须依赖用户配合。按语义使用灰蓝 #465664、蓝 #215bd6、黄褐 #8b5b0d、深绿 #21684b，配白字。沿用其他名称／代码时应明确映射。不能从子项、百分比或颜色推断阶段签收。

绘图前检查重复编号、缺失阶段／父项、父子环和跨阶段父子关系。出错时显示涉及编号和原始记录，不能静默补造、丢弃或调整任务。未知状态与不合法的依赖数组同样需要修正。缺失依赖／当前任务引用及依赖环显示提示；依赖不能转成父子归属线。


已声明的文本字段须为字符串（可选字段允许为 null 或缺省），关系字段须为有效编号，证据／历史条目须为对象。类型错误应在建立关系或初始化视图前进入诊断面板。

## 层级与浏览

层级为项目、阶段、任务及进一步登记的子任务，不设置固定业务深度上限。单阶段项目沿用相同结构。

新增一层或改变既定层级组织须由用户确认；已授权范围、既定层级内的新增任务沿用原授权。展开折叠仅改变视图，无需逐次确认。

展开节点时立即展示全部直属展示项；已分类的父任务先展示全部分类，各分类内的成员仍完整可见。更深一层保留自己的折叠状态。子项计数、导图节点和右侧子任务列表共用同一关系索引。搜索、依赖和详情条目只展开必要祖先、定位现有节点，不改变节点资格，不创建任务。

界面只使用导图＋右侧详情。任务可查看编号、标题、状态、优先级、工作内容、完成标准、直属子项、依赖、验证与证据。阶段可查看要求、明确签收和遗留事项。项目总览提供材料、历史与决策入口，长记录须可完整读取。窄窗口采用右侧覆盖面板，并提供返回画布的操作。

| 画布操作 | 行为 |
| --- | --- |
| 普通滚轮 | 上下平移，并接收触控板横向位移 |
| Ctrl＋滚轮 | 以指针位置缩放，画布内避免同时触发页面缩放 |
| Shift＋滚轮 | 左右平移，不重复叠加两个方向的位移 |
| 左键或右键拖动背景 | 平移；背景不弹出浏览器右键菜单，按钮、节点和详情保留正常右键菜单 |

处理像素、行、页三种 deltaMode，不拦截右侧详情或页面其他区域的滚动。颜色旁保留状态文字，选中外框不覆盖状态底色。按钮支持键盘操作。

## 显式展示分类

taskGroups 是可选数组，每项为 {id, parent, stage, title, taskIds, description?, tone?}。分类具有独立编号，parent 指向现有任务，stage 与该父任务一致，title 为非空标题，taskIds 明确按顺序记录成员任务编号。可选 tone 为 todo、doing、waiting、done；省略时用中性色。它仅控制展示配色，不代表任务状态或验收结果。

分类编号使用独立命名空间，在 taskGroups 内按字符串形式唯一。分类不进入 tasks，不计入任务总数，也不能成为依赖目标。任务原有 parent、依赖、状态、验收和证据保持原记录。分类只能包含该父任务的真实直属子任务，不能包含更深后代或另一个分类。更深的真实任务可分别配置自己的分类。

某父任务启用分类后，全部直属任务须在各分类中恰好出现一次。重复、未知、非直属或遗漏成员，父任务缺失／阶段不一致，分类编号重复和错误字段类型均显示诊断，不能静默修复展示。允许空分类，但其他分类仍须覆盖全部任务。分类顺序与成员顺序以显式数组为准。

展示路径变为父任务、分类、原有子任务。展开父任务显示全部分类，展开分类显示全部成员。父节点明确区分类别数与真实直属任务数；父任务详情同时保留分类入口和完整真实子任务清单。分类详情展示说明、成员和所属任务，没有自己的任务验收或阶段签收。搜索、当前任务和依赖定位会展开必要分类路径，选择和浏览不改变成员。

“超过 8 个”即 9 个及以上真实直属子任务，不计算全部后代或分类节点。在规划拆分（包括计划新增第 9 项）或开始推进相关父任务时，提出具体分类建议，获准后添加分类层或改变分类依据。在已有历史／决策中简记用户同意或拒绝的结果；拒绝后，明显变化前不重复询问。分类待确认或被拒绝时，仍可继续其他已授权工作并保持原展示。这是智能体的维护提醒，不是浏览器弹窗或数据有效性限制；大量未分类子任务仍可合法展示，也不强制每类最多 8 项。

方案获准后，智能体在既定分类依据与任务授权范围内维护显式成员，任务状态变化时核对分类归属。浏览器不按状态自动重排。新增真实业务层级仍遵循单独的层级确认规则。

## 证据与本地存储

相对证据路径基于 meta.projectRoot 和看板实际 URL 解析，不假定固定目录深度。保留可读原路径和复制操作，提供可用的 file/http/https 链接；未经验证的本地链接不能声称已可访问。拒绝 javascript、data 等可执行方案。 本地路径按实际文件名处理，#、?、% 等字符作为文件名内容编码；若需要 URL 片段或查询参数，请使用完整的 http/https/file URL。

浏览器存储键为 project-workboard:v2:<storageKey>:draft 和 :view。草稿可编辑和下载，不自动发送给智能体或写回任务 JSON。视图记录选中、展开、缩放和平移。旧编号消失时合理回退；存储失败时提示，浏览和草稿下载仍可使用。

新项目不能复用示例 storageKey，也不能删除其他项目的键。文件 URL 的存储行为随浏览器和路径变化，换文件名或浏览器后未必能读取原草稿；移动前下载重要草稿。

## 已有项目

更新技能不代表授权重写已有看板、重编号或迁移浏览器存储。迁移需要单独授权，先约定唯一数据来源。

获准迁移后，须保留任务编号、明确父子关系、依赖、状态语义、验收／签收边界、原始结果、证据路径、决策、历史和未完成事项。核验前保护原文件、草稿和视图存储。不能只复制 HTML 就声称已迁移浏览器笔记。本版本不提供自动迁移工具。
