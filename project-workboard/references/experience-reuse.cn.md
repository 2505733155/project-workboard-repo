# 经验总结与复用（中文阅读版）

[English（原文）](experience-reuse.md) | 简体中文

本文件是供人阅读的中文译本，规则以英文原文为准，修改时应同步维护中英文。智能体执行时使用英文入口引用的 `experience-reuse.md`。

用户同意执行可选的经验复用任务后，在用户审阅结束、工作目录清理之前读取本指引。

## 先筛选，再与用户选择经验

用户同意后，回顾本阶段的用户指示、审阅反馈，以及智能体观察到的有效做法。提出候选之前，检查相关的已有指令、看板条目、专题文档和技能，确认是否已有重叠指引。沿用项目的阅读入口，围绕候选主题查阅，不遍历所有文档或技能。

保留有增量价值的候选：改变了判断认识的具体误解、失败或审阅纠正；有证据支持的有效做法；或者新增的长期用户要求。常规工程义务和已有且容易找到的规则，通常无需另行总结。如果某条已有规则被反复遗漏，优先考虑在原位置改善表述、适用条件或读取入口，而不是把规则复制到另一个文件。

区分“证据已经记录”和“指引已经容易复用”。具体经验即使写在报告里，也可能埋得很深；这时可以建立简短的、按使用场景查阅的索引，链接原报告。如果已有入口已能达到这一目的，复用或更新原入口；证据保留在原位置，不复制整份报告。

对于保留的候选，简要说明发生了什么、它改变了什么判断或做法、依据是什么，以及以后何时可能用到。区分观察事实与原因解释，保留适用边界；局部性能结果、某次运行参数或一次授权例外，不能直接变成通用规则。根据经验本身需要决定说明的详细程度，不设置强制模板、评分表或候选数量。

只把筛选后的候选交给用户选择；智能体的观察仍是建议，不自动成为已采纳规则。确认选中的经验哪些仅适用于本项目，哪些属于可跨项目使用的用户偏好或工作流程。同意总结不代表所有候选都可以成为用户级规则。如果没有新增的复用价值，记录“无新增可复用经验”即可继续，不创建文件，也不再次询问是否愿意总结。

## 选择合适的保存方式

用户已有偏好的形式和位置可用时，遵循用户选择。如果用户已确定内容、范围或保存位置，直接使用，不重复询问。否则，推荐最简单且适合的方式并说明取舍；只有其他方式能够满足具体需要时，再展开讨论。

| 内容与用途 | 合适的保存方式 | 取舍 |
| --- | --- | --- |
| 项目术语、审阅要求或反复使用的项目约定 | 更新已有专题文档；需要时在 `docs/` 下创建主题集中的文档 | 明确，便于随项目维护；需要为后续智能体提供容易发现的阅读入口 |
| 应当跨项目适用的用户偏好 | 当前工具的用户级指令，或已有的用户维护参考文档 | 可以跨项目复用；需要确认范围，避免将项目专用选择扩大到其他项目 |
| 可重复执行的工作流程或方法 | 更新相关的已有技能；只有具有独立、长期复用价值时才建议新建技能 | 可以打包指令和资源；也增加了一项需要发现和维护的内容 |
| 当前工具支持、适合以后回忆的有用背景 | 工具原生的记忆能力 | 取决于工具的控制方式、可用性和调用行为；重要的必行规则仍需明确指引 |
| 第三方学习工具已经能够满足的具体需要 | 与用户选定的、可用的社区技能或工具 | 可能引入日志、自动化或依赖；推荐前须检查具体来源及实际行为 |

选择技能形式时，使用可用的技能编写工具，例如 `skill-creator`，或当前工具提供的等效流程。优先扩展相关的已有技能，避免创建重复技能。简短的项目约定通常适合放在项目文档中，无需另建技能。

记忆服务和社区技能是可选方式，不是完成此项任务的前提。对于 Codex Memories，查阅[官方记忆说明](https://learn.chatgpt.com/docs/customization/memories)及当前可用控制方式：记忆由后台生成，不一定立即完成。不要默认通过手动编辑自动生成的记忆文件来操作，也不要为了等待后台记忆更新而阻止阶段结束。如实报告已经配置或准备的内容，不宣称未经确认的内容已存入记忆。

如果考虑社区方案，明确它的仓库或包，检查其指令，并说明相关的兼容性、存储、自动化和维护要求。仅凭名称不足以比较工具。安装新依赖或更改用户级设置，应作为所选方式的一部分与用户讨论，不能将“同意总结”理解成已同意这些改动。

## 保持指令文件简短

详细经验放在主题集中的文档里，尽可能复用已有文件。术语和审阅要求等主题服务于不同活动时，可以分别维护。在当前工具识别的项目指令文件（例如 `AGENTS.md` 或 `CLAUDE.md`）中，只添加简短的用途说明和按需读取链接。

例如，指令文件可以写：

```text
撰写或修改论文时，遵循 docs/terminology.md。
阶段审阅前，读取 docs/review-guidelines.md。
```

使用项目中的真实路径和相关的读取条件。不要将指令入口变成完整的经验档案，也不要要求每个任务开始前都读取全部经验文档。用户级指令需要详细参考资料时，也遵循同样原则。

## 保存已确认的结果

用户已选定经验、适用范围和保存形式后，落实约定的改动，并检查链接或其他相关行为。在看板中记录决定、范围和保存位置；区分已采纳经验与建议，以及已执行改动与待执行事项。

如果用户拒绝这项可选任务，记录本阶段已跳过，继续清理，不重复询问。跳过某阶段的经验总结不代表项目退出看板。遵循看板已有状态约定；如果状态列表没有专门的“已跳过”状态，就在任务说明或历史中注明。
