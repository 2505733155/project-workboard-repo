# 项目工作看板（中文阅读版）

[English（执行原文）](SKILL.md) | 简体中文

本文件是供人阅读的中文译本。智能体的执行入口仍为 `SKILL.md`；规则以英文原文为准，修改时应同步维护中英文。

## 应用

使用当前 AI 工具识别的项目指令文件，例如 `AGENTS.md` 或 `CLAUDE.md`，并遵循项目已有约定。

如果不确定项目是否需要工作看板，先询问用户。如果用户拒绝，在项目指令文件中简短记录退出选择；用户重新启用前，不为该项目创建看板或调用此技能。

## 创建

优先复用项目已有看板。项目需要新建看板或重新设计看板时，先列出本技能 `assets/example/` 目录中的 HTML 文件，请用户选择案例后再继续。即使只有一个 HTML 文件，也要请用户确认；如果用户已经明确选择了文件，直接使用该选择，不重复询问。如果没有可用的 HTML 文件，请用户添加或提供案例后再继续。

用户可以替换内置的[案例](assets/example/AMPC_ISA_revision_board.html)，也可以在 `assets/example/` 中添加其他 HTML 文件。每次需要案例时，都应发现当前可用文件，不要求必须使用这个特定文件名。

检查选中的 HTML，根据用户需求调整布局和交互。替换原项目的数据、历史、完成状态及项目专用链接。为目标项目另行创建看板，保留案例原文件。本技能规定的收尾顺序优先于所选案例中的顺序。

使用实际看板路径，在项目指令文件中添加一条简短的英文规则：

> Before project work, read `<board>.html` and update it after authorized work.

即：项目工作前先读取看板，完成授权工作后更新看板。

## 维护

工作前读取看板。完成授权工作后，更新进展、下一步行动、任务状态、证据和历史，使其反映实际发生的情况。

每个阶段结束时，按以下固定顺序安排四个独立任务：

1. **独立核验与修正。** 在项目根目录写出核验要求，说明阶段或版本、核验材料、检查项目和验收标准。给用户一段引用该文件的提示词，请用户另开新对话核验。当前实施对话及其子代理不能代替这项任务。完成前记录发现的问题、修正和再次核验结果。
2. **用户审阅。** 处理用户反馈，并取得用户对本轮审阅已经结束的明确确认。
3. **经验总结与复用（可选）。** 询问一次，是否将本阶段的用户指示、审阅反馈和智能体发现的有效做法总结下来，供以后复用。如果用户拒绝，记录本阶段已跳过此项，直接进入清理，不重复询问。如果用户同意，按照[经验复用指引](references/experience-reuse.cn.md)让用户筛选经验、确认适用范围并选择保存方式。将结果及实际保存位置记录到看板中。
4. **全工作目录检查与清理。** 检查工作目录，移除已确认的临时或冗余产物，保留交付物、必要证据和用户改动。

保持技能简洁，根据实际使用反馈逐步完善。
